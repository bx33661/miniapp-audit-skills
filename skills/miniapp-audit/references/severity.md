# 严重性与验证优先级

仅对 confirmed 发现评定 severity。needs_validation 与 rejected 不携带 severity；候选的 priority 表示验证顺序，不进入已确认风险统计。

## 影响判断

说明受影响资产、攻击者权限、必要配置或交互、可达性、已证明的后果和范围。未知的全量用户、资金损失或生产权限不得写成既成影响；可说明有待核实的扩大条件。

| 等级 | 判断依据 |
|---|---|
| CRITICAL | 已证明低前提且范围广的接管、敏感数据或资金控制 |
| HIGH | 已证明有实际后果的显著数据、权限或资金边界失效 |
| MEDIUM | 已证明影响有限，或受明确条件限制的边界失效 |
| LOW | 已证明但后果较小的信息或控制问题 |
| INFO | 有证据支持的低影响观察；不替代待验证状态 |

这些是判断锚点，不是按漏洞名称套等级。客户端有 amount 字段、管理路由、云环境 ID、缺配置或缺响应头都不能自行推出严重性。给出评级理由；总体风险结合已确认影响、业务关键路径和覆盖限制解释，不取标签最大值或相加分数。

## 不确定性

evidence_level 描述证明力，status 描述主张结论。若保留 confidence，需解释来源完整性、复现稳定性或未消除的环境差异；不能用 High confidence 把 E1 提升为已确认，也不能把无证据的高影响猜测纳入最终严重性。

候选 priority 使用 P0/P1/P2/P3，按验证价值、可达性和证据成本说明顺序，不根据关键词自动填。CWE、OWASP API Top 10 或 MASVS 映射帮助定位控制类别，不决定等级。
