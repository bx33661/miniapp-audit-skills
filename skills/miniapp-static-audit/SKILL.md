# 微信小程序静态审计

## 目的

把小程序材料转化为可追溯的假设或直接证据，明确已知事实、待验证控制与覆盖限制。

一个有根据的假设应说明：输入或行为由谁控制、到达哪个安全决策、预期控制是什么，以及什么证据能确认或推翻主张。只有客户端材料时，服务端控制是待核实问题，不能断言它不存在。凭证暴露和隐私处理应定位各自实际失效的控制。

## 原则

- **模式不是漏洞。** `eval`、字符串拼接或角色参数只是线索；漏洞是缺失的边界。
- **按需要解析。** 第一轮发现可用有限提取；跨作用域和间接调用使用 AST 或人工追踪，不执行目标代码求值。
- **追踪数据，不追踪单行。** 确认值从哪里来、如何变换、最终到达哪个接口或函数。
- **定位实际控制。** 服务端授权不能由客户端标志替代；客户端隐私、凭证暴露和桥接问题按各自边界分析。
- **记录不确定性。** E0/E1 假设也是有效产出，但要准确标注。
- **按威胁模型选择。** 不要机械执行所有领域；说明覆盖范围，记录跳过项。

## 工作流

1. **建立攻击面。** 识别 API、云调用、web-view、导航与权限；聚合时保留全部调用位置、动态表达式和未解析限制。
2. **扫描密钥。** 检查凭证和敏感数据的用途、发布可达性与上下文；排除项写明证据，不按 test/example 等词自动过滤。
3. **追踪客户端可控数据。** 从页面输入、存储、导航、二维码 scene、剪贴板和网络响应出发，跟踪到敏感位置：请求、云调用、web-view URL、文件操作、渲染和认证决策。
4. **审查鉴权。** 识别角色、资源和归属校验。关注客户端可控的对象标识、租户标识、角色标志和管理接口。
5. **审查支付。** 检查价格、数量、折扣、订单状态和支付结果由谁决定。金额必须由服务端计算，回调必须验签。
6. **审查隐私。** 对比声明的权限和隐私配置与实际 API、SDK 使用；识别未同意先收集和不必要收集。
7. **审查云开发、web-view 和供应链。** 检查云函数鉴权、数据库和存储规则、web-view 域名白名单、`postMessage` 处理、插件权限和依赖风险。
8. **排序假设。** 按影响、可达性和证据成本排序，为每个假设写测试思路。

脚本：`python3 scripts/extract_endpoints.py --root <dir> --app-id <appid> --output attack-surface.json` 做第一轮发现。读取 limitations；UNKNOWN、null 和省略的未分析字段不能解释为安全或零发现。按任务选读下面的领域 reference。

## 领域问题

| 领域 | 问题 | 参考 |
|---|---|---|
| 攻击面 | 有哪些端点、云函数、web-view、存储调用和权限？哪些由用户控制？ | `references/attack-surface.md` |
| 密钥 | 是否嵌入凭证、密钥、Token 或个人信息？是有效凭证还是占位符？ | `references/secrets.md` |
| 数据流 | 客户端输入从哪里进入，如何变换，到达哪个敏感位置？ | `references/dataflow.md` |
| 鉴权 | 哪些对象、租户和角色标识由客户端控制？归属校验在哪里？ | `references/authz.md` |
| 支付 | 金额是否由服务端计算？回调是否验签、幂等、防重放？ | `references/payment.md` |
| 隐私 | 声明权限和隐私告知是否与实际收集、共享一致？ | `references/privacy.md` |

## 输出

- 规范化攻击面清单。
- 带上下文和脱敏的密钥、敏感数据候选。
- 带来源、路径、实际控制和残余不确定性的数据流记录。
- 鉴权、支付、隐私、云开发和 web-view 假设。
- 带预期证据和优先级的测试用例。

## 质量门

- 每个假设都有文件与行号，或端点与参数引用。
- 假设写明待验证的控制；确认主张有独立可核验的失效依据。
- 密钥候选经过上下文验证并脱敏。
- 覆盖说明写明哪些领域已审查、部分审查或跳过。
- 状态与 E0–E3 一致；确认需通过共享发现契约，证据强度不按静态/动态工具划分。

## 安全边界

- 不执行反编译代码或不可信依赖。
- 未经明确授权，不使用发现的密钥访问线上系统。
- 在所有笔记和输出中脱敏凭证和个人信息。
