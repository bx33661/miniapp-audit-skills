# 最小可追溯的可读性辅助

只在某个具体分支、参数来源或调用关系阻碍审计时使用。短变量名、压缩代码或主观质量分数都不触发全项目还原。原始包与解包源码保持不变，辅助结果不能替代原始证据。

## 允许的辅助

- 优先局部格式化、模块定位、列出调用关系和旁注，限定到正在核实的安全决策。
- 在独立工作副本中展开排版时保留语句、表达式、求值顺序、异常处理与异步边界。格式化无法解析的代码应原样保留，记录阻碍。
- 优先在笔记中给符号增加作用域内的语义标签。确需改名时，必须有可靠语法和绑定信息，只改同一绑定及其引用；没有这些能力就保留原名。
- 语义标签需要由赋值来源、参数传递与用途支持；例如仅看到变量用于请求参数，不能断言其就是当前用户身份。
- 注释区分直接观察和推断，说明推断依据及未解决分支。不要把“疑似鉴权”改写成“已验证安全”。

## 必须保持的边界

- 禁止按文本做全局 `a` → `userId` 一类替换。不同模块、闭包与作用域的同名变量可能代表不同对象。
- 不更改对象属性、对外导出名、协议字段、框架钩子或字符串中的名字，避免改变接口契约。
- 不提取函数、展开闭包、合并条件、改写循环、简化短路表达式或调整 Promise/回调；这些操作可能改变控制流和副作用。
- 不通过执行未知 bundle 猜语义；需要隔离执行时另按 [obfuscated-bundle.md](obfuscated-bundle.md) 的条件处理。
- 不根据抽样命名规律批量重写其他文件，不生成全局映射、置信度总分或没有消费方的还原报告模板。

## 追溯要求

每个实际使用的辅助片段都应能定位到原文件和范围：记录原文件路径及哈希、模块/函数/作用域、原始行列或字节范围、辅助副本位置、使用的工具及变换说明。若做绑定改名，逐项记录原符号、新标签与绑定范围；不能只保留一张全局名字字典。

发现仍引用原始位置。辅助副本改变行号时，提供已核对的位置对应关系；映射缺失或不可靠就回到原文引用，不能生成看似精确的虚假行号。source map 也要先核对模块、索引和版本。

没有独立输出 schema，因此不强制新增 `restoration-map.json`、`quality_report`、`restoration-report.md` 或其他平行契约。将使用过的辅助与限制随材料证据保存，并在 `evidence/material-check.json` 的 `quality.issues` 或 `next_actions` 中说明可读性阻碍。该文件遵循 [material-check-output.schema.json](../assets/material-check-output.schema.json)。

可读性改善只帮助核实事实，不增加证据强度。原始材料不能支持的控制流、身份来源或服务端行为，必须保留为未知。
