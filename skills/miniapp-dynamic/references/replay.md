# 请求重放与改参

构造或解释 HTTP 对照实验时使用。保留原请求语义，先建立成功基线，每次改变一个维度。

## 归一化

记录方法、目标 URL、必要请求头、原始 body、抓取时间、账号角色，以及 sign、timestamp、nonce、一次性 Token 等易变字段。保留表单顺序、重复参数、编码和二进制格式；不要凭解析后的字典重建被签名的原始字节。

让 HTTP 客户端依据实际 URL 与 body 重算 Host、Content-Length 和连接字段。按客户端能力处理压缩，保留小程序实际发送的 Referer、User-Agent 与必要业务头，不凭浏览器习惯补头。凭证在受限执行环境中注入，证据使用脱敏副本。

重定向先停止并检查新目标是否在范围内，再决定是否跟随及是否携带认证信息。不得因重放扩大到第三方或其它环境。

## 基线与改动

先发送未修改请求，确认预期业务结果。基线失败时记录错误来源，不比较改参成败。使用当前会话，保持原始请求与实际发送请求可追溯。

| 改动维度 | 示例 | 需要证明的事实 |
|---|---|---|
| 对象或租户 | orderId、tenantId、unitCode | 访问或操作超出当前身份的授权范围 |
| 功能或角色 | 管理端点、role、isAdmin | 服务端实际接受了不应允许的能力 |
| 金额或状态 | quantity、discount、status | 服务端结果违反计价或状态规则 |
| 方法或结构 | 改方法、增加字段、改变类型 | 具体控制可被绕过，或字段被不当赋值 |
| 会话 | 去除或替换测试身份凭证 | 受保护结果不再绑定正确身份 |

只改一个实验变量；签名等派生字段需同步重算时记录原因和规则。无法保持有效请求则记录 BLOCKED，不把签名失败当作鉴权通过。

## 解释响应

比较业务错误、对象标识、关键字段和独立可读状态。HTTP 状态、长度或哈希差异是线索，确认需要可解释的边界结果。401/403 可能来自鉴权、网关或签名；超时可能来自网络或目标不稳定，都不能直接断言安全控制存在。

保存脱敏的正常请求/响应、实际改动请求/响应、身份、时间和预期/实际对照。结果分类见 `dynamic-testing.md`。按 `safety.md` 的速率和停止条件执行，不暴力破解签名或枚举真实用户。
