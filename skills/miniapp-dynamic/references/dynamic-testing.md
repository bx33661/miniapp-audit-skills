# 对照实验与结果判断

验证具体安全假设时使用。发送前写清目标环境、资产、身份、正常基线、单变量改动、预期拒绝或隔离行为，以及什么观察会推翻主张。

## 实验设计

| 场景 | 最小对照 | 有效信号 |
|---|---|---|
| 对象授权 | A 访问自己的对象，再仅替换为 B 的授权测试对象 | 返回或改变了 B 的具体资源 |
| 功能授权 | 正常特权基线与低权限账号对照 | 低权限身份实际完成受保护操作 |
| 状态或资金 | 保持业务输入，仅改变待检字段；使用测试状态 | 独立读取到不符合业务规则的服务端结果 |
| 重放或竞态 | 先证明单次基线，再在批准的次数、速率和窗口内对照 | 产生了额外业务效果或违反幂等约束 |
| 注入或文件处理 | 有明确来源与敏感位置，选择最小可观察差异 | 证明数据越过预期解释或访问边界 |

注入验证按问题选择本地、差异、时间或带外方法；不默认优先时间盲注，不把固定 payload 清单当覆盖证明。无回显或拦截只说明观察受限。

## 结果状态

| status | 含义 | 证据要求 |
|---|---|---|
| CONFIRMED | 具体边界失效且后果可说明 | E2/E3，成功基线、改动、预期/实际、复现、证据引用 |
| INCONCLUSIVE | 已尝试，但结果不能区分原假设与其它原因 | 实际观察及无法判断的原因 |
| BLOCKED | 缺账号、签名、网络、权限或测试材料，未完成有效实验 | 精确阻塞点及所需条件 |
| FALSE_POSITIVE | 有足够对照证据推翻原主张 | 正常基线、改动、复现与反驳证据 |

Payload 未触发、401/403、WAF 或空响应不能单独作为 FALSE_POSITIVE。只对已验证的具体路径下结论，不外推整个接口、角色或应用安全。

## 保存结果

输出字段由 `../assets/dynamic-test-output.schema.json` 定义，结构中的 baseline 保存 request/response，mutation 描述唯一改动，expected/actual 写安全预期与实际结果。INCONCLUSIVE/BLOCKED 的 reason 写未消除的解释或缺少条件。证据必须可按 evidence_refs 定位，不能只有“请求成功”等结论文字。

环境、时间、账号角色、包版本与请求来源按实际记录，不混用不同版本和环境。只使用授权测试数据，最小证据成立后停止；状态变更和竞态执行前先检查 `safety.md`。
